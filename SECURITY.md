# Безопасность

## Сообщение об уязвимости

Не публикуйте сведения об уязвимости в открытой задаче вместе с рабочими
учётными данными или содержимым базы данных. Передайте владельцу репозитория
описание затронутого маршрута, условия воспроизведения и ожидаемое исправление.

## Настройки перед публикацией

- задайте уникальный `SECRET_KEY` из менеджера секретов;
- отключите `SEED_DEMO_USER` и `SEED_DEMO_ADMIN`;
- удалите ранее созданные демонстрационные аккаунты из рабочей базы;
- обслуживайте приложение только через HTTPS;
- включите `SESSION_COOKIE_SECURE=1`;
- ограничьте доступ к SQLite-файлу пользователем приложения;
- создавайте резервные копии перед применением новых миграций.

Пример переменных находится в `.env.example`. Приложение не загружает этот
файл автоматически: значения должны передаваться средой запуска.

## Встроенные меры

Пароли сохраняются в виде хешей Werkzeug. Изменяющие запросы защищены
CSRF-токеном, привилегированные маршруты проверяют роль на сервере, а ответы
получают базовые заголовки защиты от MIME-sniffing и встраивания во фреймы.
