# Развёртывание приложения

## Подготовка окружения

Создайте виртуальное окружение, установите зависимости из `requirements.txt` и задайте переменные
окружения по образцу `.env.example`. Файл `.env` с реальными секретами не должен попадать в Git.

Для опубликованного приложения обязательно:

- задайте постоянный случайный `SECRET_KEY`;
- отключите создание демонстрационных пользователей через `SEED_DEMO_USER=0` и `SEED_DEMO_ADMIN=0`;
- включите `SESSION_COOKIE_SECURE=1`, если приложение доступно по HTTPS;
- ограничьте доступ к каталогу `instance`, где находится SQLite-база.

Перед запуском новой версии выполните:

```bash
python check_project.py
```

## Запуск

Команда `python app.py` предназначена для локальной разработки. В опубликованной среде запускайте фабрику
`app:create_app` через WSGI-сервер, подходящий для выбранной операционной системы и платформы. HTTPS следует
завершать на reverse proxy или средствами платформы размещения.

Приложение само создаёт каталог `instance`, применяет отсутствующие миграции и загружает начальные учебные
материалы при старте. Процесс приложения должен иметь право записи в этот каталог.

## Проверка состояния

После развёртывания запросите служебный адрес:

```text
GET /health
```

Ответ со статусом `200` и значением `"database": "ok"` подтверждает, что приложение запущено и может читать
базу данных. Этот адрес можно использовать для health check платформы, но он не заменяет проверку входа,
открытия курса и сохранения прогресса.

## Обновление версии

1. Сделайте резервную копию `instance/study_guide.sqlite3`.
2. Остановите старый процесс приложения.
3. Получите новую версию кода и установите актуальные зависимости.
4. Запустите приложение: миграции выполнятся автоматически.
5. Проверьте `/health` и основные пользовательские сценарии.

При неудачном обновлении остановите приложение, верните предыдущую версию кода и восстановите сделанную
перед обновлением копию базы данных.
