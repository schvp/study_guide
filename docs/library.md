# Библиотека учебных материалов

## Источник данных

Версионируемые материалы находятся в `library_materials/<course-slug>/`. Каждый материал состоит из JSON-файла
с метаданными и Markdown-файла с текстом. Загрузчик `library_content.py` проверяет обязательные поля, допустимые
значения, уникальность адреса и позиции, а затем передаёт данные приложению.

При старте приложение синхронизирует материалы с таблицей `library_materials` по сочетанию курса и `slug`.
Изменения версионируемого материала в репозитории считаются источником истины и обновляют соответствующую запись
SQLite. Материалы, созданные преподавателем через интерфейс, продолжают храниться только в базе данных.

## Метаданные

JSON-описание содержит:

- `course` — адрес курса;
- `slug` — постоянный адрес материала;
- `chapter_position` — связанная глава;
- `position` — порядок в каталоге;
- `title` и `description`;
- `category`, `difficulty` и `material_type`;
- `estimated_minutes` — расчётное время чтения;
- `status` — `draft` или `published` (по умолчанию `published`);
- `content_file` — имя Markdown-файла;
- необязательный `resource_url`.

Проверка всего набора выполняется командой:

```bash
python validate_library.py
```

## Пользовательский прогресс

Избранное, отметка прочтения и последнее открытие хранятся в `library_user_progress`. Составной первичный ключ
не допускает несколько записей одного пользователя для одного материала. Внешние ключи удаляют отметки вместе
с аккаунтом или материалом.

Изменение прогресса выполняется только POST-запросами с CSRF-токеном и после серверной проверки пользователя.
Запрос может изменять только строку текущего аккаунта. Черновые и отсутствующие материалы не принимают отметки.

Каталог использует прогресс для персональных фильтров и сводки. Профиль показывает процент прочтения и пять
последних открытых материалов. Страница главы рекомендует до четырёх опубликованных материалов, связанных с ней.

## Добавление материала

1. Выберите главу и следующий свободный номер позиции.
2. Создайте JSON и Markdown с одинаковым числовым префиксом.
3. Используйте уникальный `slug`, который не меняется при правке заголовка.
4. Напишите самостоятельный учебный текст и проверьте технические утверждения.
5. Запустите `python validate_library.py` и полный `python check_project.py`.
6. Зафиксируйте один законченный материал отдельным коммитом.

Не добавляйте в материал рабочие учётные данные, содержимое пользовательской базы или ссылки с секретами в
параметрах URL.
