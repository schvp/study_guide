# Работа с базой данных

## Расположение и назначение

По умолчанию приложение хранит данные в `instance/study_guide.sqlite3`. В этой базе находятся аккаунты,
курсы, главы, прогресс, результаты тестирования, лабораторные попытки и преподавательские настройки.
Каталог `instance` исключён из Git: рабочую базу нельзя добавлять в репозиторий.

## Миграции

Схема обновляется функцией из `migrations.py` при создании приложения. Выполненные версии записываются в
таблицу `schema_migrations`, поэтому каждая миграция применяется только один раз.

При изменении схемы:

1. добавьте новую функцию миграции в конец `MIGRATIONS`;
2. присвойте ей следующий номер версии и понятное имя;
3. не изменяйте миграции, которые могли выполниться в существующей базе;
4. добавьте тест обновления как новой, так и уже заполненной базы;
5. запустите `python check_project.py`.

Изменение старой миграции не обновит базы, где её версия уже записана, и приведёт к различию схем между
установками.

## Резервное копирование

Перед обновлением приложения остановите процесс, использующий SQLite, и скопируйте файл базы в защищённое
место с датой версии в имени. Проверяйте, что копия открывается SQLite и содержит таблицу
`schema_migrations`.

Резервные копии могут содержать email, хеши паролей и учебные результаты. Для них нужны те же ограничения
доступа, что и для рабочей базы; их нельзя публиковать в репозитории или передавать вместе с исходным кодом.

## Восстановление

1. Остановите приложение.
2. Сохраните повреждённую базу отдельно для диагностики.
3. Поместите проверенную копию по пути `instance/study_guide.sqlite3`.
4. Запустите приложение и дождитесь применения более новых миграций, если они есть.
5. Проверьте `/health`, вход пользователя и отображение ранее сохранённого прогресса.

Не заменяйте базу во время работы приложения: это может оставить активные соединения со старым файлом и
привести к потере новых записей.
