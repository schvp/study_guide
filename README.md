# study_guide
Учебное пособие по дисциплине «Схемотехника цифровых систем»

## Запуск

```bash
python -m venv .venv
```

Активируйте виртуальное окружение, установите зависимости и запустите приложение:

```bash
pip install -r requirements.txt
python app.py
```

Откройте <http://127.0.0.1:5000> в браузере.

## Аккаунты и прогресс

Пользователи и отметки о прохождении разделов хранятся в SQLite-файле
`instance/study_guide.sqlite3`. Пароли в открытом виде не сохраняются:
в базе хранится их хеш. Прогресс привязан к аккаунту и сохраняется отдельно
для каждого раздела. Вход доступен по логину или email. При регистрации
логин должен содержать 3–32 латинских символа, цифры, точку, дефис или
подчёркивание.
Для аккаунтов предусмотрены роли `student` (учащийся), `teacher` (преподаватель)
и `admin` (администратор). Новые и ранее созданные пользователи получают роль
учащегося; выбрать привилегированную роль при регистрации нельзя. Администратор
может просматривать пользователей и менять их роли в разделе `/admin/users`;
собственную роль изменить нельзя.
Раздел `/content-management` доступен только преподавателям и администраторам;
проверка роли выполняется на сервере при каждом запросе.
В разделе управления курсами преподаватели и администраторы могут создавать
и редактировать курсы; данные проверяются сервером, запросы защищены CSRF-токеном
и изменения сохраняются в SQLite.
В интерфейсе управления также показываются главы каждого курса и формы для
добавления и редактирования глав. Преподаватели и администраторы могут добавлять
главы, изменять их описание и учебный материал, а также менять порядок глав.
Прогресс и история сохраняются при переупорядочивании, поскольку ID глав остаются
неизменными.
Внешние ключи связывают отметки прогресса с пользователем и главой; при удалении
пользователя или главы соответствующие отметки также удаляются. В профиле
отображается история завершения глав; ранее пройденные разделы добавляются в неё
при обновлении базы данных. Сводка профиля показывает процент прохождения,
результаты тестов, выполненные лабораторные работы, статистику по каждой главе и
десять последних учебных действий. В профиле можно сбросить прогресс текущего курса,
чтобы начать прохождение заново; журнал истории завершений при этом сохраняется.

Для учебных целей по умолчанию создаётся демо-аккаунт:

```text
Логин: test
Пароль: test

Логин администратора: admin
Пароль администратора: admin
```

Демо-аккаунт учащегося можно отключить через `SEED_DEMO_USER=0`, администратора —
через `SEED_DEMO_ADMIN=0`. Перед публикацией приложения отключите оба демо-аккаунта.
Учётные данные `admin / admin` предназначены только для разработки; не используйте
их в production. Настройки отключают только автоматическое создание аккаунтов:
если они уже есть в БД, удалите их или смените пароли вручную. Пароли не хранятся
в открытом виде, в БД записываются хеши.

Главы курса открываются по порядку на страницах `/course/1`, `/course/2` и
далее. Перейти к следующей главе можно после завершения предыдущей; это
проверяется сервером. Курсы и главы хранятся в таблицах `courses` и `chapters`
той же SQLite-базы; при первом запуске текущий курс и восемь глав добавляются
автоматически. Исходные материалы хранятся в `course_materials/<slug>/`:
JSON-файл описывает курс, позицию главы, название, описание и имя Markdown-файла
с текстом. При запуске материал добавляется в главу, если её содержимое пустое;
уже заполненный учебный текст не перезаписывается. Прогресс существующих
пользователей сохраняется при инициализации.
Каталог `/courses` показывает курсы из базы данных, а страница `/courses/<slug>`
отображает программу выбранного курса. Доступ к главам и прогресс работают
отдельно для каждого курса.

Материалы библиотеки хранятся отдельно в таблице `library_materials` и связаны
с курсом. Для материала предусмотрены тип, название, описание, ссылка или
текстовое содержимое и порядок отображения. Преподаватели и администраторы могут
создавать, редактировать, переупорядочивать и удалять материалы через раздел
управления контентом. Поддерживаются ссылки только на HTTP(S)-ресурсы.

Курсы и главы поддерживают статусы «Черновик» и «Опубликован». В управлении
контентом новые записи создаются черновиками и публикуются явно. В каталоге,
учебных страницах, библиотеке и прогрессе отображается только опубликованный
контент; существующие на момент миграции записи остаются опубликованными.

Структура SQLite обновляется последовательными миграциями из `migrations.py`.
Применённые версии и время их выполнения записываются в таблицу
`schema_migrations`. Для нового изменения схемы добавляйте новую миграцию в конец
списка `MIGRATIONS`; уже применённые миграции не редактируйте. Каждая миграция
выполняется в транзакции и при ошибке откатывается.

В приложении есть навигация по разделам «Главная», «Обучение», «Библиотека»,
«Лаборатория», «Тестирование» и «Профиль». Библиотека выводит материалы из
таблицы `library_materials`. Раздел лаборатории объединяет восемь интерактивных
работ, показывает их доступность и прогресс учащегося. Работы открываются
последовательно, а каждый запуск и результат сохраняются в
`laboratory_attempts`. Последние завершённые попытки, набранные баллы и время
выполнения отображаются в разделе лаборатории. В разделе
тестирования доступны тренировочные задания по всем восьми главам: вопросы с
одним и несколькими вариантами ответа и числовые задачи. После отправки сервер
проверяет ответы и показывает результат с пояснением по каждому вопросу.
Попытки и ответы сохраняются в SQLite отдельно для каждого пользователя;
последние результаты отображаются в разделе тестирования. Вопросы начального
банка определены в `assessment_bank.py`, а их схема и данные попыток создаются
последовательными миграциями. Преподаватели и администраторы управляют вопросами
в разделе `/content-management`: можно создавать, редактировать, публиковать,
скрывать, перемещать и удалять вопросы. Для вариантов ответа указывайте по одной
строке `код|текст`; правильные коды для вопросов с несколькими ответами
разделяются запятыми. У числовых заданий можно настроить допустимую погрешность.
Начатая попытка использует неизменяемые снимки вопросов, поэтому последующая
правка или удаление вопроса не меняет проверку уже начатого теста.
Вопросы можно помечать начальным, средним или продвинутым уровнем сложности.
При старте учащийся выбирает уровень, а система случайно выбирает вопросы из
подходящего опубликованного набора. В настройках главы преподаватель задаёт
размер варианта от 1 до 20 вопросов; если подходящих вопросов меньше, тест
содержит все доступные. Там же можно ограничить продолжительность попытки от
1 до 1440 минут и число попыток от 1 до 100. Учащийся видит таймер и количество
использованных попыток, а сервер не принимает ответы после истечения времени и
не позволяет начать тест после исчерпания лимита.

Для локальной разработки приложение создаёт временный секрет для сессий при
запуске. Чтобы сессии оставались действительными после перезапуска, задайте
постоянный `SECRET_KEY` в окружении перед запуском. Для production используйте
уникальный секрет из менеджера секретов, включите HTTPS и задайте
`SESSION_COOKIE_SECURE=1`.

## Проверка структуры учебных материалов

Перед публикацией курса можно проверить JSON-описания глав, наличие Markdown-
файлов и последовательность позиций одной командой:

```bash
python validate_course.py
```

Для другого каталога материалов передайте его первым аргументом:

```bash
python validate_course.py path/to/course_materials
```

Команда выводит число курсов и глав, а при ошибке возвращает ненулевой код
завершения. Это удобно использовать в CI перед запуском приложения.
