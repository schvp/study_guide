## Назначение

Асинхронный FIFO передаёт поток слов между независимыми тактовыми доменами. Источник записывает данные со своим тактом, приёмник читает со своим. Очередь сглаживает кратковременную разницу скоростей и обеспечивает согласованную передачу многобитного слова.

FIFO не гарантирует бесконечную пропускную способность: если средняя скорость записи выше чтения, очередь в итоге заполнится.

## Память и указатели

Двухпортовая память имеет независимые интерфейсы записи и чтения. Двоичный write pointer адресует следующую запись, read pointer — следующее чтение. Дополнительный старший бит отличает полный оборот кольцевого буфера.

Каждый указатель изменяется только в собственном домене. Для вычисления статусов его копию нужно передать в другой домен.

## Почему используется код Грея

При двоичном переходе 0111 → 1000 меняются четыре бита. Независимая синхронизация могла бы создать смешанное значение. Указатель преобразуют в код Грея, где соседние значения отличаются одним битом, и только затем пропускают каждый бит через синхронизаторы.

Локальная логика сохраняет двоичную копию для адреса памяти и Gray-копию для передачи.

## Признак empty

В домене чтения FIFO пуст, когда следующий или текущий read Gray pointer совпадает с синхронизированным write pointer — точная формула зависит от того, регистрируется ли статус заранее. Из-за синхронизации освобождение empty может задержаться на несколько тактов, что безопасно: данные уже существуют, но чтение начнётся чуть позже.

## Признак full

FIFO полон, когда следующий write pointer догнал read pointer на один полный оборот. В типичной степенной глубине Gray-сравнение требует инверсии старших битов синхронизированного указателя чтения. Формулу нельзя переносить между разными разрядностями без проверки.

Снятие full также консервативно задерживается, что уменьшает производительность, но предотвращает перезапись непрочитанных данных.

## Правила интерфейса

Запись выполняется только при write enable и NOT full. Чтение — только при read enable и NOT empty. Поведение при нарушении нужно определить: игнорирование операции, флаг ошибки или счётчик переполнений.

## Сброс

Оба указателя сбрасываются в ноль в своих доменах. Асинхронное включение сброса допустимо, но снятие синхронизируют отдельно. Если один домен начинает работу раньше другого, статусы должны оставаться безопасными.

## Проверка

Тестируют разные отношения частот и фаз, заполнение до границы, опустошение, одновременное чтение и запись, переход указателей через ноль и случайные паузы. Счётчик эталонной очереди должен доказать отсутствие потерь, дубликатов и изменения порядка.
