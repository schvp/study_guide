## Асинхронный и синхронный подходы

В асинхронном счётчике выход одного триггера тактирует следующий. Переключения распространяются каскадом, поэтому промежуточно возникают ложные коды. Такой счётчик прост, но его максимальная скорость уменьшается с числом разрядов, а декодирование состояний может формировать импульсные помехи.

В синхронном счётчике все триггеры получают общий такт. Комбинационная логика заранее вычисляет следующее состояние. Задержка определяется логикой между регистрами, а не суммой задержек всех триггеров.

## Выбор числа разрядов

Для счётчика по модулю M требуется минимальное n, при котором 2^n ≥ M. Счётчику mod-10 нужны четыре разряда. Шесть из шестнадцати комбинаций остаются неиспользованными, и для них нужно определить поведение восстановления.

Счётчик должен либо переходить из недопустимого состояния в известное допустимое, либо гарантированно никогда в него не попадать. Для реального устройства предпочтительно самовосстановление после помехи или включения питания.

## Таблица переходов

Запишите текущее состояние Q и следующее состояние Q+. Для обычного возрастающего двоичного счётчика младший бит меняется каждый такт. Следующий разряд меняется, когда все младшие разряды равны единице.

Для D-триггера вход D непосредственно равен следующему значению соответствующего бита. Для T-триггера вход T равен единице, если бит должен переключиться. Для JK-триггера можно использовать режим переключения J = K = 1 либо минимизировать функции возбуждения по таблице.

## Пример mod-6

Последовательность трёхразрядного счётчика: 000, 001, 010, 011, 100, 101 и снова 000. Состояния 110 и 111 недопустимы. В безопасном варианте оба переводятся в 000 на следующем фронте.

Для каждого входа D строят отдельную карту Карно по таблице переходов. Недопустимые состояния нельзя бездумно считать X, если требуется самовосстановление: им уже назначен конкретный переход.

## Разрешение и направление

Сигнал enable удобнее включать в функцию следующего состояния, чем логически блокировать тактовый сигнал. При enable = 0 регистр загружает собственное текущее значение. Это сохраняет единое тактовое дерево и не создаёт укороченных импульсов.

Для реверсивного счётчика направление выбирает прибавление или вычитание единицы. В программируемой логике это естественно описывается операцией над вектором, а синтезатор строит цепь переноса.

## Терминальный счёт и каскадирование

Сигнал terminal count показывает достижение последнего состояния. Если он используется комбинационно, нужно учитывать задержки декодирования. Для каскада синхронных счётчиков terminal count младшего блока подают на enable старшего, сохраняя общий такт.

Регистрированный terminal count устойчивее для внешнего интерфейса, но появляется на такт позже. Выбор зависит от протокола.

## Сброс и начальное состояние

Синхронный сброс действует на активном фронте и участвует во временном анализе. Асинхронный сброс может немедленно установить состояние, но его снятие должно быть синхронизировано. Начальное состояние нужно задавать явно, а не рассчитывать на случайные значения после питания.

## Проверка счётчика

Проверьте полный цикл, перенос через границу, удержание при выключенном enable, смену направления и выход из каждого недопустимого состояния. Для mod-M убедитесь, что период последовательности равен M и ни одно допустимое состояние не пропущено.

При моделировании полезно автоматически сравнивать состояние с эталонным вычислением по модулю. На временной диаграмме отдельно проверяют, что декодированные управляющие выходы не содержат коротких импульсов между фронтами.
